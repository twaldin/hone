Abstract

We describe Hone, a local-first, durable optimization CLI built around a single coding-session kernel of AIDE + GEPA + Pi lineage. The same kernel is applied at three levels: to concrete artifacts, to the task-builders that pose optimization problems, and — under bounded, human-gated conditions — to the optimizing controller itself. The flagship experiment asks a falsifiable question: can a coding agent find a measurably better version of itself, twice in succession, on work it has never seen? We outline the campaign protocol, the trust architecture that treats the agent’s own scores as unreliable, and the reporting discipline under which either answer is publishable.

Keywords: optimization, self-improvement, sandboxed evaluation, pre-registration, holdout transfer.

1.Introduction

*Durability is not an implementation detail: interrupted search that cannot resume is search that quietly re-samples, and re-sampling is how results stop being comparable.

The entire interface is equation (1): the user states an objective in plain language, and the system earns the improvement — together with the evidence for it. Hone persists every intermediate state locally,1 so a crash or a week away loses nothing.* There is no separate “meta” system: the kernel that improves a JSON parser is the kernel that improves the process which improves it. What changes between uses is the target — never the discipline around it.

Definition 1 (Capsule). A frozen, sandboxed build-or-optimization benchmark: a pinned source tree, a deterministic harness, and a protected scoring oracle. Once admitted, a capsule does not change for the life of the campaign.

The capsule panel spans real open-source workloads — JSON parsers, allocators, codecs, bundlers, resolvers — alongside owner-authored coding tasks, weighted equally in the terminal estimand so that neither family can dominate the conclusion.2

2.The Campaign Protocol

The experiment proceeds in stages, each conditional on the last, with human approval required at both promotion points. Figure 1 gives the topology; the protocol below gives the invariants.

  1. Stage A — develop G1.

    The starting controller G0 runs the inner loop across a frozen development panel, proposing candidates. The best-supported is selected as G1, subject to independent evaluation and the first human gate.

  2. Stage B — paired tournament, G2.

    On a fresh panel, G0 and G1 attempt identical work in paired runs — same capsules, same budgets, same seeds where the harness permits — isolating the controller as the only variable. The stage yields G2, behind the second gate.

  3. Terminal — the untouched holdout.

    G0, G1, and G2 are compared on holdout capsules that no controller, prompt, or selection decision ever saw. This is the pre-registered estimand.

  4. Report — either way.

    RelayBench publishes the outcome as success or failure against thresholds registered before the first run. Violations of the protocol are published alongside results.3

3.An Architecture of Distrust

†The trusted runtime stays deliberately small: admission, snapshots, sandboxes, evaluators, budgets, persistence, promotion. Everything else is mutable — and therefore untrusted.

A self-improving optimizer is the last system whose scores should be taken on faith. Hone therefore assumes its own agent will game any measurement it can reach, and measures accordingly:† everything the agent can mutate is scored from outside the walls. Table I summarizes the properties.

Table I — Trust properties of the evaluation regime
PropertyMechanism
networknone — no egress from any evaluation
rootfsread-only; writable scratch only where declared
lifecyclea fresh container for every evaluation; mutation and evaluation in separated images
timingmeasured by a trusted parent process, never self-reported
oraclesscoring logic protected from the code under test; sealed measurement tooling
panelscorpus and holdouts frozen before search begins
reviewcapsules and results examined by parties incentivized to find the seam
gatesno promotion at G1 or G2 without explicit human approval
recursiondepth bounded; budgets reserved for ancestors up front
secretsstrict source and credential isolation from the agent

Successor controllers are additionally evaluated independently of the loop that proposed them; all runs persist and replay end to end.
