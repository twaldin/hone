01

one kernel, three uses

no separate “meta” system. the same durable kernel that improves a JSON parser is the one that improves the process that improves it. what changes between uses is the target — never the discipline around it.

PID 1ahone --target=artifactS (durable)

point hone at a concrete objective — build time, binary size, throughput, conformance-preserving refactors. runs are resumable and every intermediate state is persisted locally; a crash or a week away loses nothing.

PID 1bhone --target=task-builderS (held-out eval)

the programs that construct optimization tasks are themselves artifacts. hone tunes them against held-out evaluation, so the tasks it later attempts are better-posed than the ones it started with.

PID 1chone --target=self --depth≤2 --gatedS (bounded)

bounded recursive self-optimization: the controller searches for improved versions of itself, with recursion depth capped, budgets reserved up front, and every promotion contingent on independent evaluation and a human gate.

02

how the campaign works

a falsifiable question: can a coding agent find a measurably better version of itself, twice in a row, on work it has never seen? every step is designed so that either answer is trustworthy.

STEP 1/4

capsules — the unit of evidence

a capsule is a frozen, sandboxed build-or-optimization benchmark: a pinned source tree, a deterministic harness, and a protected scoring oracle. the panel spans real OSS workloads — JSON parsers, allocators, codecs, bundlers, resolvers — alongside owner-authored coding tasks. once admitted, a capsule does not change for the life of the campaign.

STEP 2/4

stage A — develop G1

the starting controller G0 runs the inner optimization loop across a frozen panel of development capsules, proposing candidate controllers. the best-supported candidate is selected as G1 — subject to independent evaluation and a mandatory human approval gate before promotion.

STEP 3/4

stage B — paired tournament, G2

on a fresh panel, G0 and G1 attempt identical work in paired runs — same capsules, same budgets, same seeds where the harness permits. the pairing isolates the controller as the only variable. the stage yields G2, again behind a human gate.

STEP 4/4

terminal — the untouched holdout

G0, G1, and G2 are compared on terminal holdout capsules that no controller, prompt, or selection decision ever saw during development. this is the pre-registered estimand: adjacent-generation transfer measured on work the campaign could not have overfit.

04

architecture of distrust

a self-improving optimizer is the last system whose scores should be taken on faith. hone assumes its own agent will game anything gameable — the trusted runtime stays small and frozen, and everything mutable is scored from outside the walls.

sandbox isolation

  • networknone — no egress from any evaluation
  • rootfsread-only; writable scratch only where declared
  • capabilitiesdropped to the floor
  • lifecyclea fresh container per evaluation
  • containersmutation / evaluation images separated

gaming resistance

  • timingmeasured by a trusted parent, never self-reported
  • binariessealed tooling the agent cannot rewrite
  • oraclesscoring protected from the code under test
  • panelscorpus and holdouts frozen before search

independent review

  • reviewersincentivized to find the hole
  • successorsevaluated independently of the proposing loop
  • replayruns persisted, replayable end to end

human gates

  • G1 gateno stage-A promotion without approval
  • G2 gateno stage-B promotion without approval
  • depthrecursion bounded; ancestor budgets reserved
  • secretsstrict source / credential isolation

if the result is real, it survives all of this.
if it isn’t, relaybench says so — same report, same thresholds. $ exit 0
