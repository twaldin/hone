01Kernel

One kernel, three uses

There is no separate “meta” system. The same durable coding-session kernel that improves a JSON parser is the one that improves the process that improves it. What changes between uses is the target — never the discipline around it.

1.1

Optimize artifacts

A concrete objective — build time, binary size, throughput, conformance-preserving refactors. Runs are resumable; every intermediate state is persisted locally. A crash or a week away loses nothing.

1.2

Optimize task-builders

The programs that construct optimization tasks are themselves artifacts. Hone tunes them against held-out evaluation, so the tasks it later attempts are better-posed than the ones it started with.

1.3

Optimize the optimizer

Bounded recursive self-optimization: recursion depth capped, budgets reserved up front, every promotion contingent on independent evaluation and a human gate.

02Method

How the campaign works

A falsifiable question: can a coding agent find a measurably better version of itself, twice in a row, on work it has never seen? Every step is designed so that the answer — either answer — is trustworthy.

2.1

Capsules → Sandbox

Frozen benchmarks enter a hardened boundary: network none, read-only root, fresh container per evaluation.

2.2

Stage A · G0 → G1

Inner loop on the frozen development panel proposes candidates; the best-supported becomes G1.

Human gate
2.3

Stage B · G0 vs G1 → G2

Paired runs on a fresh panel — same capsules, budgets, seeds. The controller is the only variable.

Human gate
2.4

Terminal · G0 G1 G2

Holdout capsules unseen during development. The pre-registered estimand: adjacent-generation transfer.

a

Capsules — the unit of evidence

A pinned source tree, a deterministic harness, a protected scoring oracle. Real OSS workloads — parsers, allocators, codecs, bundlers, resolvers — plus owner-authored tasks. Once admitted, a capsule never changes.

b

Independent promotion

Candidate controllers are evaluated independently of the loop that proposed them; promotion additionally requires explicit human approval at G1 and G2.

c

Pairing isolates the variable

Stage B runs G0 and G1 on identical work under identical budgets, with identical seeds where the harness permits — differences attribute to the controller, not the draw.

d

The holdout cannot be overfit

No controller, prompt, or selection decision ever touches the terminal capsules during development. What transfers there was learned, not memorized.

04Trust

Architecture of distrust

A self-improving optimizer is the last system whose scores should be taken on faith. The trusted runtime stays small and frozen; everything the agent can mutate is scored from outside the walls.

4.1Sandbox isolation

Networknone — no egress from any evaluation
Rootfsread-only; writable scratch only where declared
Capabilitiesdropped to the floor
Lifecyclea fresh container for every evaluation
Containersmutation and evaluation in separated images

4.2Gaming resistance

Timingmeasured by a trusted parent process, never self-reported
Binariessealed measurement tooling the agent cannot rewrite
Oraclesscoring logic protected from the code under test
Panelscorpus and holdouts frozen before search begins

4.3Independent review

Reviewcapsules and results examined by parties incentivized to find the flaw
Successorscandidates evaluated independently of the proposing loop
Replayruns persisted and replayable end to end

4.4Human gates

G1 gateno Stage-A promotion without explicit human approval
G2 gateno Stage-B promotion without explicit human approval
Depthrecursion bounded; budgets reserved for ancestors up front
Secretsstrict source and credential isolation from the agent

If the result is real, it survives all of this. If it isn’t, RelayBench says so — same report, same thresholds.
