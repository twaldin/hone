01

One kernel, three uses

No separate “meta” system. The same durable kernel that improves a JSON parser improves the process that improves it. Only the target changes — never the discipline around it.

1A

Optimize artifacts

Point Hone at a concrete objective — build time, binary size, throughput, conformance-preserving refactors. Runs are resumable; every intermediate state persists locally. A crash or a week away loses nothing.

1B

Optimize task-builders

The programs that construct optimization tasks are artifacts too. Hone tunes them against held-out evaluation, so the tasks it later attempts are better-posed than the ones it started with.

1C

Optimize the optimizer

Bounded recursive self-optimization: recursion depth capped, budgets reserved up front, every promotion contingent on independent evaluation and a human gate.

02

The campaign

A falsifiable question: can a coding agent find a measurably better version of itself, twice in a row, on work it has never seen? Either answer is trustworthy.

1

Capsules — the unit of evidence

A frozen, sandboxed benchmark: pinned source tree, deterministic harness, protected scoring oracle. Real OSS workloads — parsers, allocators, codecs, bundlers, resolvers — plus owner-authored tasks. Once admitted, a capsule never changes for the life of the campaign.

2

Stage A — develop G1

Starting controller G0 runs the inner loop across a frozen development panel, proposing candidate controllers. The best-supported candidate becomes G1 — after independent evaluation and a mandatory human gate.

3

Stage B — paired tournament

On a fresh panel, G0 and G1 attempt identical work in paired runs: same capsules, same budgets, same seeds where the harness permits. The pairing isolates the controller as the only variable. Output: G2, behind a second gate.

4

Terminal — untouched holdout

G0, G1, G2 compared on holdout capsules no controller, prompt, or selection decision ever saw. The pre-registered estimand: adjacent-generation transfer on work the campaign could not have overfit.

▲ Human approval required at G1 and G2. No exceptions.
03

RelayBench — either way

Thresholds registered before the first run. When the campaign concludes, RelayBench publishes success or failure against those thresholds. The goalposts do not move.

04

Architecture of distrust

A self-improving optimizer is the last system whose scores should be taken on faith. Hone assumes its own agent will game anything gameable — and measures from outside the walls.

Sandbox isolation

  • networknone — no egress from any evaluation
  • rootfsread-only; writable scratch only where declared
  • capsdropped to the floor
  • lifecyclea fresh container for every evaluation
  • imagesmutation and evaluation separated

Gaming resistance

  • timingmeasured by a trusted parent process, never self-reported
  • binariessealed measurement tooling the agent cannot rewrite
  • oraclesscoring logic protected from the code under test
  • panelscorpus and holdouts frozen before search begins

Independent review

  • reviewcapsules and results reviewed by parties incentivized to find the hole
  • successorscandidates evaluated independently of the loop that proposed them
  • replayruns persisted and replayable end to end

Human gates

  • G1 gateno Stage-A promotion without explicit approval
  • G2 gateno Stage-B promotion without explicit approval
  • depthrecursion bounded; ancestor budgets reserved up front
  • secretsstrict source and credential isolation from the agent

If the result is real, it survives all of this. If it isn’t, RelayBench says so.
