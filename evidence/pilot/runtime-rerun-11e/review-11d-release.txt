   - **What this is:** `_run` only learns that `docker run` exited through `process.poll()`. That call never waits, so it misses an exit the kernel has not reported yet. If it says "still running" and the deadline has passed, the loop gives up at `:529-530` or `:537`. After both pipes have closed, `:555-559` polls first, then reads the clock and gives up.
   - **Problem:** The Docker CLI is a multithreaded Go program. When it exits, Linux closes its pipes before the process becomes collectable by `waitpid`. During that short gap, the frame is fully read and the exit code (0) is already fixed, but `poll()` still returns `None`. A deadline that lands in this gap, or a delayed host reader (host, CLI and container all share CPU 6), gives `timeout` and unscored infrastructure. Cleanup then kills and waits; the kill is ignored because the process is already exiting, so the receipt records `outcome: timeout` with `exit_code: 0` and a valid frame.    - **Fix:** Use the same kill-then-wait pattern as inside the container. Add `import signal` and a helper:
     ```python
     def _expire(process, seconds):
     ```
