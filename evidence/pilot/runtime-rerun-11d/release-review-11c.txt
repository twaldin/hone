1. **A worker that has finished but is still shutting down at the deadline gets "time limit, score 0"** (`pilot/verification.py:426-437`, caller `:458-463`)
   - **Defect class:** worker I/O at the exit/deadline boundary. This is the same class as review stop 11b, not a policy question.
   - **What this is:** The fix only keeps the result once `waitid(... WNOHANG | WNOWAIT)` reports an exit. `waitid` is the call that asks whether the worker has exited. If that call still sees the worker running and the deadline has passed, line 437 returns `None`. That becomes the trusted "exceeded the 10 second time limit" result, scored 0.
   - **Problem:** The worker writes its full result frame and calls `_exit` before the deadline. But Linux only reports the exit after the kernel frees the process's memory. The sandbox allows up to 256 MB (`pilot/program.py:38`) on one CPU (`:38-39`), so this cleanup can take time. Here is a concrete order of events:
     1. The frame is written at deadline−2 ms.
     2. The checker reads the whole frame (`:440-442`).
     3. The next `waitid` call still sees the worker as not exited, because its memory is being freed.
     4. `select` waits until the deadline. The pipe has not closed yet, because the kernel releases the worker's files only after freeing its memory.
     5. Line 436-437 returns `None`.

     So a pass that was fully delivered turns into a wrong-answer 0. That is a wrong score, not an unscored failure. How long the memory cleanup takes is my inference. I have not observed this happening in a real run.
   - **Fix:** When the deadline passes and no exit has been seen, call `_kill(child)` first. Then wait for the worker with a blocking `os.waitid(os.P_PID, child, os.WEXITED | os.WNOWAIT)`.
     - If our SIGKILL ended the worker (`si_code == CLD_KILLED`, `si_status == SIGKILL`), it was still running: return `None`, as now.
     - Otherwise it had already started its own exit before the kill. A kill sent during exit does not change the exit status. In that case, reuse the same bounded read as lines 430-435 and return the bytes.

     The worker gets no extra running time, because SIGKILL is still sent at the deadline. Add a Docker regression for both cases: the worker started exiting before the deadline (frame kept), and the worker still running at the deadline (score 0).
   - **If we skip it:** A finished result, including a pass, can still be lost at the deadline and silently scored 0 inside the rankings.
